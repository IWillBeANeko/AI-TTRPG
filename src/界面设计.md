### **第 1 章 核心数据模型（TypeScript，直接可用）**

type EraId = 'dawn' | 'glory' | 'end'; // 黎明/辉煌/终末
type ImprintType = 'causal' | 'echo' | 'butterfly' | 'anchor';
// 因果链(青) | 信息回响(蓝) | 蝴蝶效应(品红) | 锚点锁定(金)
type SkillId = '洞察' | '潜行' | '口才' | '学识' | '共情' | '战斗' | '仪式';
type Attitude = 'trust' | 'friendly' | 'neutral' | 'wary' | 'hostile' | 'unknown';
type DiceState = 'crit' | 'success' | 'fail' | 'fumble';
interface Imprint { // 时间印记：全局唯一驱动对象
id: string;
type: ImprintType;
trigger: string; // 触发条件（显示文案）
consequence: string; // 后果描述（显示文案）
loopCreated: number; // 产生于第几 Loop
permanent: boolean; // 锚点锁定=true，回溯不清除
applied: string[]; // 已生效的界面ID列表（防止重复生效）
}
interface NpcState {
id: string; // prophet|elder|iris|baker|priest|envoy|warden|
// merchant|orphan|echo|ghost|reaper|karsas
name: string;
attitude: Attitude;
metLoops: number[]; // 在哪些 Loop 见过
knowledge: string[]; // TA 当前知道的信息（影响对话树）
isGhost: boolean; // 时间残影/幽灵态（半透明渲染）
alive: boolean;
}
interface GlobalState {
loop: number; // 当前 Loop，从 1 起
era: EraId;
stability: number; // 时间线稳定度 0-100，起始 100
act: 1|2|3|4|5; // 当前主线幕
routeFlags: Record<string, boolean>; // 分支旗标（见第3章路由表）
imprints: Imprint[]; // 印记库（含历史 Loop）
npcs: Record<string, NpcState>;
anchorMemory: { integrity: number; conflicts: string[] }; // C-2 用
aidLevel: number; // B-7 民兵援助度 0-130%
branchMap: { current: string; explored: string[] }; // C-3 用
paradoxLevel: number; // C-4 悖论污染度 0-100
saveSlots: object[]; // 锚点存档（回溯目标）
history: TurnLog[]; // E-3 结算用
}

**稳定度演算规则**（所有界面共用）：
	- 大成功 crit → +5｜成功 → +0｜失败 → -8｜大失败 fumble → -15
	- 蝴蝶效应印记激活 → 额外 -10（一次性）
	- 锚点锁定印记激活 → 回溯时稳定度 +10（修复加成）
	- 稳定度 ≤ 30：顶栏警示灯品红闪烁 + 全局噪点密度×2（视觉映射）
	- 稳定度 = 0：强制触发终局 B 路由（时间线崩坏，见第 3 章）
### **第 2 章 全局规则引擎**

#### **2.1 骰子判定（E-1 弹窗由任何选项卡按需唤起）**

roll20 + skill_mod + aid_bonus >= DC → success
结果=20 → crit（大成功，青→金粒子）
结果=1 → fumble（大失败，紫黑裂纹）

	- 修正来源：NPC 态度（trust/friendly → +2）、相关印记（echo 类型若记录了该线索 → 优势=取两次掷骰高值）
	- 关闭锁定：结果展示 ≥800ms 内禁止点击关闭（防误触）
	- 队友援助：点击援助头像 → 本骰 +1d4 优势
#### **2.2 印记产生规则（底部金色提示条的唯一数据源）**

| **印记** | **产生时机** | **生效逻辑** |
| --- | --- | --- |
| 因果链 causal | 在同一 Loop 内完成"事件A→事件B"闭环 | B 事件自动成功（免骰） |
| 信息回响 echo | 跨 Loop 获得了之前 Loop 的信息 | 对话选项解锁隐藏行（"？"图标点亮） |
| 蝴蝶效应 butterfly | 改变了 NPC 命运节点（救/杀/告密） | 该 NPC 相关后续全部变体 + 稳定度 -10 |
| 锚点锁定 anchor | 玩家主动使用锚点保存记忆 | 回溯后此记忆保留（permanent=true） |
#### **2.3 Loop 循环与回溯**

	- 触发回溯：稳定度 ≤10、剧情节点死亡、或玩家主动激活锚点
	- 回溯执行：loop+1、非 permanent 印记清除、NPC 态度回到锚点存档值、锚点记忆保留
	- 每次回溯 → 弹出 E-3 结算页 → 玩家从三个"下一 Loop 起点"中选择（见 4.21）
### **第 3 章 界面路由总表（React Router 实现）**

游戏启动 → A-1 → A-2 → A-3 →（Loop 起点三选一，默认 B-1）
B-1 → {解锁B-2} → B-2 → {谈判成功→B-3 / 失败→B-4}
B-3 → {潜行成功→B-5 / 失败→被俘线→B-4}
B-4 → B-5 → B-6 → B-7 → B-8
B-8 → 终局路由判定（见 4.11）→ C-1~C-4 中已触发者插入 B-7 前后 / 或直接 D-1/D-2/D-3
C-1 → C-2 → C-3 → C-4（转折链，由各自触发条件插入主线）
任意场景界面 → 点击NPC头像 → E-2（浮层，返回原界面）
任意判定需求 → E-1（浮层，返回原界面）
任意 Loop 结束/回溯 → E-3

**转折触发条件**：C-1=第二幕后且有 2+ NPC 态度为 hostile｜C-2=使用过锚点 ≥2 次｜C-3=B-6 完成｜C-4=稳定度曾 <40

### **第 5 章 一个完整回合的执行伪代码（供 AI 对齐流程）**

玩家点击选项卡 →
① 若选项需判定 → 挂起当前界面 → 渲染 E-1 → 等待骰子结果
② 结果写入 TurnLog → 更新 stability（按第1章规则）

→ 底部提示条滑入新行（渲染 ImprintBar.entries 末位）
④ 检查转折触发条件（第3章）→ 若命中 → 路由插入 C 界面
⑤ 检查 stability≤10 / 剧情死亡 → 触发回溯 → E-3
⑥ 否则按选项定义的跳转字段 → router.push(目标界面)
